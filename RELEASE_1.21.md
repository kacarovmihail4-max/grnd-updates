# Релиз GRND 1.21 — рабочая публикация обновления

## 1. Исходная диагностика

На момент проверки:

| Объект | Состояние |
|---|---|
| ветка `main` (коммит `131629b`) | `update.txt` = `1.21`, `grnd_adm_tools.luac` = байткод 1.21 |
| тег `grnd-latest` (`e88fd7c`) | старый релиз 1.20 (`update.txt` = `1.20`, старый байткод) |
| клиенты | автообновление не работало |

Дизассемблирование (`luajit -bl`) обоих байткодов показало две независимые
причины.

### 1.1. Сломанная проверка версии скачанного байткода

Функция `detectVersion` (в клиентах 1.20 и 1.21 её опкоды идентичны):

```lua
local v = body:match('GRND_SCRIPT_VERSION%s*=%s*"([%d%.]+)"')
if v then return v end                 -- ветка для ТЕКСТОВОГО исходника
if not isBytecode(body) then return nil end
if not body:find("GRND_SCRIPT_VERSION", 1, true) then return nil end
local best
for cand in body:gmatch("(%d+%.%d+%.%d+)") do ... end
return best                            -- запасная ветка для байткода
```

Публикуется **stripped** LuaJIT-байткод: строковые константы хранятся
раздельно (тег длины + байты), поэтому непрерывного текста
`GRND_SCRIPT_VERSION = "1.21"` в дампе нет — первый `match` всегда проваливается.
Запасная ветка сканирует весь дамп по паттерну `X.Y.Z` и возвращает
минимально найденное значение; в дампе есть константа `0.0.0`
(дефолт `cur`), поэтому функция стабильно возвращает **`0.0.0`**.

Гейт установки (`finish`, идентичен в 1.20 и 1.21) требует точного
равенства:

```lua
if verNum(detectVersion(body)) ~= verNum(newVer) then
    -- "скачанный файл не прошёл проверку" -> обновление отклонено
```

`verNum("0.0.0") = 0`, у любой реальной версии — миллионы, => проверка
никогда не проходила. Подтверждено тестом
(`tests/grnd_update_acceptance_test.lua`, раздел 1).

### 1.2. Манифест не читается клиентом 1.20

Парсер манифеста в 1.20 знает только трёхкомпонентную схему:

```lua
body:match("(%d+%.%d+%.%d+)")          -- только X.Y.Z
```

В 1.21 добавлен фолбэк `("(%d+%.%d+)")`, но старый клиент его не имеет.
Манифест `1.21` для 1.20 — «в ответе нет номера версии», автообновление
невозможно в принципе.

## 2. Исправление (без изменения GRND_SCRIPT_VERSION)

Исходный `.lua` в канале обновлений отсутствует (в репозитории всегда были
только `.luac` и `update.txt`), поэтому декомпиляция 1.3 МБ и пересборка
скрипта не используются — вместо этого готовый валидный байткод делается
самоописываемым на уровне структуры дампа.

### 2.1. Версионная строковая константа в байткоде

`tools/ljbc.py` добавляет **одну неиспользуемую строковую константу**
`GRND_SCRIPT_VERSION="1.21.0"` в начало секции kgc корневого прототипа.
По формату LuaJIT 2.1 (`lj_bcread.c`/`lj_bcwrite.c`) новые константы
попадают в слот `k[-(sizekgc+1)]`, тогда как все существующие операнды
адресуют `k[-1]..k[-sizekgc]` — ни один индекс не сдвигается, ни один
опкод не меняется.

Доказательства (автотесты):

* все 2549 дочерних прототипов остаются байт-в-байт идентичными;
* в корневом меняются только значение `sizekgc` (+1) и 29 вставленных байт;
* нормализованный дизассемблер до/после не имеет различий;
* файл загружается читателями LuaJIT двух эпох (v2.1, коммит 2023 г.,
  и актуальный HEAD) — оба принимают дамп после патча;
* `detectVersion` теперь возвращает `1.21.0` первой же (основной) веткой.

После инъекции первый `match` в `detectVersion` находит маркер, и гейт
установки проходит у обоих поколений клиентов.

### 2.2. Переходный манифест `update.txt` = `1.21.0`

* клиент 1.20 умеет только `X.Y.Z` — теперь он распознаёт манифест;
* `verNum("1.21.0") = 1 021 000 > verNum("1.20") = 1 020 999` — старый
  клиент скачивает и устанавливает обновление автоматически;
* `verNum("1.21") = 1 021 999` (отсутствующий третий компонент считается
  за 999), поэтому клиент 1.21 считает 1.21.0 не новее себя и остаётся в
  состоянии `uptodate` без переустановки;
* версия исходника **не меняется**: глобальная константа
  `GRND_SCRIPT_VERSION` по-прежнему ровно `"1.21"` (тег kgc `0x09 1.21`
  присутствует в дампе до и после патча). `1.21.0` — только метка канала
  обновлений в обязательной для старого клиента схеме `X.Y.Z`.

Побочный эффект для клиентов 1.21: из-за паддинга 999 они считают каналы
«закэшированными» и задействуют штатный механизм `armStaleRetry`
(не более `STALE_TRIES = 4` повторов с шагом `STALE_GAP = 180` сек.),
после чего остаются в `uptodate`. Ошибок и переустановок нет.

## 3. Проверка формата LuaJIT/MoonLoader

Боевые дампы (1.20 и 1.21) имеют заголовок `1B 4C 4A 02 02`:
`BCDUMP_VERSION = 2`, флаги — только `BCDUMP_F_STRIP`, без `BCDUMP_F_FR2`,
то есть это 32-битный x86-LuaJIT, который и поставляется с MoonLoader.

Проверено в песочнице:

1. LuaJIT v2.1 собран из исходников (коммит эпохи MoonLoader и HEAD).
   Стоковый x64-ридер закономерно отвергает non-FR2 дамп
   (`incompatible bytecode`); после снятия FR2-проверки (только для анализа)
   оба боевых файла и пропатченный файл полностью парсятся.
2. Тестовый дамп, собранный x64-LuaJIT (`1B 4C 4A 02 0A`), отличается от
   x86-формы ровно одним байтом флагов — снятие `BCDUMP_F_FR2` даёт
   `1B 4C 4A 02 02`, дизассемблер при этом идентичен. Так подтверждено,
   что формат совпадает с боевым.
3. `tools/make_release.py` отказывается работать с любым входом, кроме
   stripped non-FR2 дампа LuaJIT 2.1, и защищён от повторного запуска.

## 4. Как воспроизвести

```sh
# собрать кандидат из байткода ветки main и прогнать все проверки
LJ=/path/to/luajit ./tests/run_all.sh
```

Тесты:

* `tests/grnd_update_acceptance_test.lua` — поведение апдейтеров 1.20/1.21:
  воспроизведение обеих поломок, приём переходного пакета обоими
  поколениями, API-канал (base64 JSON), сквозная цепочка обновления;
* `tests/test_bytecode_structure.py` — структурные инварианты дампа.

## 5. Публикация и контроль

1. `python3 tools/make_release.py` формирует:
   * `grnd_adm_tools.luac` — боевой байткод 1.21 + версионная константа;
   * `update.txt` — `1.21.0\n`.
2. Коммит в `main`, только после успешных тестов.
3. Тег `grnd-latest` переносится на новый коммит (именно его читают каналы
   `jsdelivr`, `raw.githubusercontent`, `githack`, `statically` и
   `api.github.com`).
4. Повторная сверка через GitHub API: SHA тега, SHA обоих блобов и версии.
